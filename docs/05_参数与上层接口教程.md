# 参数与上层接口教程

在仓库根目录执行；`$projectPython`沿用README中的虚拟环境解释器。默认值集中于`mmclip/config.py`，均是可复现起点，并非线上调优结论。

## 1. 训练温度与对照

```powershell
# 两个线性头+可学习温度；初始τ=0.07，inverse temperature≤100
& $projectPython -m mmclip train --steps 60 --temperature 0.07 --max-logit-scale 100 --out runs/train-learned
# 同数据、同随机种子和初始头，固定温度对照
& $projectPython -m mmclip train --steps 60 --temperature 0.07 --fixed-temperature --out runs/train-fixed
```

`training.json`记录loss、每步温度、最终logit_scale、学习率、实际batch大小及可训练参数。默认batch_size=32，样例仅6行，实际取6；steps是优化器更新次数。数据打乱后，单行尾批被跳过，避免单样本InfoNCE没有负例却出现“loss=0”的误解。

`--learning-rate 0.01`为固定特征演示的默认值，不能据此直接配置真实模型训练。真实数据需要保留按来源文档隔离的训练/验证/测试划分；固定与学习温度两条训练日志本身不是Recall消融。

新checkpoint写入schema_version=2；加载器兼容旧版只有text/image矩阵的checkpoint。温度只影响训练损失，查询仍输出归一化投影向量。

## 2. 建库与HNSW扫描

```powershell
& $projectPython -m mmclip build --backend faiss --kind hnsw --hnsw-m 16 --ef-construction 200 --ef-search 64 --out runs/index-reviewed
& $projectPython -m mmclip evaluate --hnsw-m 16 --ef-construction 200 --ef-search 64
& $projectPython -m mmclip evaluate --sweep --m-values 16 32 --ef-values 64 128 256 --ef-construction 200 --repeats 5
```

CLI评测默认仍使用6条合成向量。要评真实向量，直接调用`evaluate`或`sweep(vectors, items, held_out_queries, ...)`。输出记录参数、ANN近邻重合率、查询P50/P95及序列化字节数；使用Flat作近邻基准，不是领域人工标注Recall。

manifest v2保存efConstruction和index_version。版本来自向量字节、元数据、编码指纹和索引参数；它是本地快照标识，不是外部数据库事务版本或完整FAISS文件签名。读取旧manifest会保留旧实现的efConstruction=80，不会悄悄冒充已经按200重建。

## 3. 服务配置

```powershell
& $projectPython -m mmclip serve --index runs/index-reviewed --port 8001 --queue-capacity 128 --max-batch 16 --max-delay-ms 5 --cache-size 128 --cache-ttl-seconds 3600 --request-timeout-seconds 10
```

`/health`返回实际配置。缓存为单进程编码LRU+TTL；最多128项，不是128个会话。过期项访问时移除，容量淘汰也会清理；不提供跨进程共享、后台清理或持久化。队列容量不包括已经开始计算的批次，多worker会各有一份模型、队列和缓存。

5ms是合批窗口目标，不是操作系统调度的硬实时保证；实际排队还包含前批计算和事件循环唤醒。延迟日志使用高精度perf_counter，TTL使用单调时钟。等待超时不会强制杀死线程/GPU计算，关闭服务时也会等待已接收批次结束。这不是全服务的硬执行隔离或全局限流。

## 4. 上层RAG调用

```powershell
$request = @{query='医院设备采购'; top_k=3; candidate_k=6; lambda_mult=0.55} | ConvertTo-Json
$evidence = Invoke-RestMethod 'http://127.0.0.1:8001/v1/retrieve' -Method Post -Body ([Text.Encoding]::UTF8.GetBytes($request)) -ContentType 'application/json; charset=utf-8'
$evidence.chunks | Format-Table chunk_id, text, score
```

参数：query非空且最多2048字符，top_k为1～50，candidate_k为1～100且不小于top_k，lambda_mult在0～1且有限。λ越大越偏向相关性。接口输入只支持文本；现有`/search`仍使用diversity字段，`/encode`接收一条query，由服务端动态合批。

| 返回字段 | 含义 |
|---|---|
| chunks[].chunk_id | 稳定业务ID，与FAISS行号分开 |
| chunks[].text | 原始证据文本；不拼上层Prompt |
| chunks[].image_url / image_reference | 已有URL可为空；本地样例只有相对路径标识 |
| chunks[].score / rank | 原始余弦相关性分数和MMR选中顺序，score不保证随rank递减 |
| chunks[].source_doc | doc_id、paragraph_id和source |
| estimated_total_tokens / token_estimate_method | 粗略文本估算与算法说明，非精确tokenizer计数 |
| index_version / encoder | 追踪快照与表示空间 |
| mmr_metrics | 候选数、返回数、λ、缩减比例及同K条平均余弦对照 |
| request_id | 与X-Request-ID响应头和服务日志关联 |

对照本次实际返回见[retrieve.json](../examples/expected/retrieve.json)。固定编码器只认识示例文本，任意未知句子返回422；接真实Chinese-CLIP后才能处理任意支持范围内的文本。
