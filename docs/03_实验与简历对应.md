# 实验与简历对应

| 简历中的内容 | 当前代码 | 当前证据范围 |
|---|---|---|
| Dataset/DataLoader、清洗和配对 | `data.py`、`features.py`、`training.py` | 元数据校验、合成样本和特征训练；真实图像批次导出待权重接入 |
| Chinese-CLIP、冻结主干、投影层 | `encoders.py`、`training.py` | 真实Torch头训练已验证；Chinese-CLIP实际权重未验证 |

| NumPy增量MMR | `vectors.py` | 与独立逐项遍历实现进行随机输入对照 |
| FastAPI、队列、批量和缓存 | `api.py`、`batching.py` | 本地API测试、批次顺序、超时、满队列和缓存 |
| 领域收益、上层系统集成 | 待领域数据与真实服务 | 当前不提供提升百分比或真实集成成果 |

## 推荐实验顺序

1. 相同固定特征比较NumPy与FAISS Flat；邻居和内积应一致，平分结果允许不同顺序。
2. 比较Flat与HNSW。记录M、efConstruction、efSearch、向量数、维度、ANN Recall@K与P50/P95。小样本延迟容易受启动与计时开销影响。
3. 比较相同候选的相关性排序与MMR。记录相同K条的平均两两余弦、证据覆盖和错误选入样本，而不是只看列表是否更不同。
4. 有真实图文对后比较原模型与投影适配模型，在独立验证集计算图文匹配Recall@K。训练loss下降不是独立检索提升。
5. 测并发请求。分别记录排队时间、编码时间、吞吐、错误和P95；本初版队列不代表全服务全局限流。

`python -m mmclip evaluate` 报告的是近似邻居相对Flat的召回，索引序列化字节数也不是进程峰值内存。需要峰值内存时另用进程资源采样，保留测量方法。

## 可以怎样解释初版

“我先给编码阶段定义了稳定输入输出，用固定特征独立验证FAISS索引、来源映射和MMR；再补充冻结双塔特征上的投影训练及有界批量编码服务。模型编码器与向量接口分离，后续真实数据可沿相同协议接入。”

实际面试叙述以你亲自完成并验证的模块为准。`docs/验证结果.md`记录此初版的运行检查，不是课题组既往实验记录。

新增`evaluate --sweep`支持参数扫描，`train --fixed-temperature`支持温度对照。它们是实验入口；没有真实独立标注时，不能据此声称领域Recall提升或去重率提升。完整判断见[实现细节审核](04_实现细节审核与参数同步.md)。
